# Alias

Separate wallet identities for different Solana apps. Fund them through Privacy Cash from your main wallet, and return funds the same way. Your main wallet stays separate: no direct public funding link. (Address separation is not anonymity — timing, amounts and off-chain data can still allow correlation.)

## Install (2 minutes)

The extension is already built. Nothing to install or build.

1. Chrome → `chrome://extensions` → enable Developer mode → **Load unpacked** → pick the `dist` folder (the one with `manifest.json` directly inside).
2. Start the funding page from this folder: `npm run companion` (or `node scripts/serve-companion.mjs`). It serves http://localhost:8765; keep it running while funding or returning.
   - Alternative: upload `companion-dist/` to any static HTTPS host and put that URL in Alias → Settings → Funding page.
3. Updating from an older version: if your current vault holds no funds, remove the old Alias extension first and load the new `dist`, so the first funding of each alias is fast (see "First funding" below).

### Solana RPC

Some public RPC servers refuse requests from browser extensions (you may see `403 Access forbidden`). Alias tries a list of public servers and moves on automatically. For the most reliable demo, create a free RPC URL (for example at Helius) and paste it into Alias → Settings → "Your own RPC". It is tried first.

### First funding of an alias

Before the first deposit, the Privacy Cash SDK looks for funds the alias already owns in the pool. For an alias whose 12 words were generated by this Alias install, that is provably nothing, so Alias skips the history and starts at the pool's current end: seconds. For an imported phrase (or a vault made with v0.2.0 or older) it must download and check the pool's whole history once, which can take several minutes. Progress shows in the Alias window and on the funding page.

(Developers: `npm install && npm run build` rebuilds `dist/` from source.)

## The flow you asked for

- **Create an alias quickly**: open Alias → set a password → write down the 12 words → pick "Trading" → done. More aliases are one click from Home.
- **Fund it from your main wallet without leaking it**: Home → **Fund privately** → amount → choose when the pool pays the alias (Right away / In 1 hour / Tomorrow) → your main wallet (Phantom/Solflare) signs one deposit into the Privacy Cash pool → the pool pays the alias. Two separate pool transactions; the alias address never appears in your main wallet's history.
- **Return**: Home → **Return privately** → it defaults to the main wallet that funded the alias → choose timing → alias deposits into the pool → pool pays your main wallet.

## What actually stays private (read this once)

- **On chain, nothing names both wallets.** The deposit transaction contains your main wallet and the pool's accounts only; the payout is sent by the Privacy Cash relayer to the alias. (Checked against the SDK source; see MILESTONES.md.)
- **Timing and amount can still match them up.** Depositing 0.05 and receiving ≈0.05 two minutes later on a brand-new address is easy to connect. Use "In 1 hour" or "Tomorrow" for real use, and avoid round, unique amounts. "Right away" is there for demos.
- **The RPC server you use sees both too**: the deposit checks your main wallet's balance and the alias's activity goes through the same server, from the same browser. Same kind of off-chain link as the relayer.
- **The Privacy Cash relayer sees both legs** (it relays your deposit and pays the alias), and so could link them off-chain. Alias cannot hide that from the relayer.
- **Everything the alias does after funding is public**, like any wallet. Separation, not invisibility.

## Your acceptance run (the only steps that need you)

Everything below needs real Chrome, Phantom installed, and a small amount of SOL (~0.05). Keep amounts tiny; Privacy Cash takes a fee per withdrawal (shown before you confirm; the relayer currently reports 0.35% + rent).

1. Load the extension, run `npm run companion`, create the vault and a Trading Alias.
2. Settings → Enable mainnet (tick the consent box). Limits default to small values; adjust in Settings if needed.
3. Home → Fund privately → 0.02 → keep **Right away** for the recording → Continue. Pick Phantom on the funding page, approve the deposit in Phantom. Watch the ops window: deposit confirmed → pool pays the alias → Explorer links for both legs. (Try "In 1 hour" once afterwards: the window shows the scheduled payout, Home shows "waiting in the pool", and the toolbar icon gets a badge when it's due.)
4. Open https://jup.ag → Connect wallet → pick **Alias** in Jupiter's own picker → the approval window recommends Trading Alias for jup.ag → Use this Alias.
5. Make a tiny swap. Review the decoded effects in the Alias approval window, approve once, watch confirmation and the received token.
6. Sell back to SOL, then Home → Return privately → it already shows your Phantom wallet as the destination → confirm both legs → check the Explorer links.

If a leg stalls: nothing is ever resent automatically. Open History → the operation → **Recheck status** or **Continue the withdrawal**. Your deposit stays in your shielded balance (owned by the alias key, recovered by your 12 words) until the withdrawal goes through.

## Demo script (~2.5 min)

1. (15s) "Every app I connect to sees the same wallet. Alias gives each app its own identity." Open the popup: mascot, one Trading Alias, balance.
2. (40s) "Fund it privately from my main wallet." Fund privately → 0.02 SOL → fee estimate → Phantom signs the pool deposit → ops window: deposit confirmed on Solscan, pool pays the alias, second Solscan link. "Two separate pool transactions. My main wallet never touches the alias."
3. (40s) "Jupiter discovers Alias like any wallet." jup.ag → Connect → Alias → approval window: 'jup.ag · Use Trading Alias here' → connected. Make the tiny swap, approve in Alias, token lands.
4. (30s) "And funds come back the same way." Return privately → destination is already my Phantom → both legs confirm → Solscan. Point at the timing choice: "For real use I'd pick Tomorrow, so the deposit and the payout don't line up in time."
5. (15s) History screen: every operation journaled, Explorer links, recoverable with 12 words. "Separation, not magic: trades under an alias are still public. But the funding link isn't."

## What's verified vs. not

See `MILESTONES.md` for the full evidence log. Short version: everything is implemented and tested in real Chromium except the live-network legs (Privacy Cash mainnet round trip, real Jupiter trade, real Phantom signing) — those are your acceptance run above, because this build environment has no route to Solana RPC or the relayer.

## Security notes

- Alias never asks for your main wallet's seed phrase or private key; it only ever sends it one unsigned deposit transaction, and verifies the returned signature byte-for-byte before relaying.
- Alias keys: derived from your 12-word phrase (m/44'/501'/i'/0'), encrypted vault (AES-256-GCM, PBKDF2 600k), unlocked seed only in session storage, auto-lock.
- Per-origin, per-network grants with exact origin matching. Every signature has its own approval window.
- Mainnet is off until you explicitly enable it; per-transaction and per-operation limits; unverifiable transactions cannot be approved on mainnet.
- Operations are journaled (encrypted) before submission and never auto-resent; unknown status stays unknown until verified on chain.
